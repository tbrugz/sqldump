
## steps

1. Set a Fixed Output Timestamp

```xml
    <properties>
        <project.build.outputTimestamp>2026-01-01T00:00:00Z</project.build.outputTimestamp>
    </properties>
```

2. Verify and Upgrade Outdated Plugins

    `mvn artifact:check-buildplan`

3. Strictly Define Environment baselines

    Even with proper Maven configuration, discrepancies in the external environment can break reproducibility.

    1. Enforce identical JDKs: A major JDK version upgrade can slightly alter generated bytecode. Use identical JDK vendors and versions across machines.

    2. Fix line endings: Windows uses CRLF line breaks while Unix environments use LF, which changes file hashes. Standardize line endings inside your Git repository using a `.gitattributes` file.

    3. Avoid dynamic dependencies: Lock all versions down entirely and never use dynamic version ranges (e.g., `[1.0,)`) or unpredictable snapshots.

4. Test Local Reproducibility

    Once your setup is complete, test the build to confirm that consecutive runs yield identical binaries.Build and install your project into your local cache:

    `mvn clean install`

    Rebuild the project separately and compare it against the previously cached files:
    
    `mvn clean verify artifact:compare`

    If the outputs match exactly, your verification will report a success. If they differ, you can pass the outputs to diffoscope to pinpoint the exact bytes or hidden timestamps causing the variance.

## extra tips

Count and List All Extensions Automatically:  
`find . -type f | grep -oE "\.[^./]+$" | sort | uniq -c`

Show files with '\r' (windows line ending):  
`grep -lR $'\r$' * | grep "src/main"`

Git: show timestamp of last commit

    ISO 8601 (Local Timezone): git show -s --format=%ci
    ISO 8601 (Strict UTC): git show -s --format=%cI
    Unix Timestamp: git show -s --format=%ct
    Human-readable/Relative (e.g., "2 hours ago"): git show -s --format=%cr
